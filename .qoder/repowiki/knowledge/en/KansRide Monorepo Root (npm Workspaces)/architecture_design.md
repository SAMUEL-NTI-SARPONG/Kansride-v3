Monorepo root orchestrates a multi-package workspace (`packages/*`, `apps/*`) via npm workspaces. Five shared packages are declared as internal modules through path aliases in `tsconfig.base.json`: `@kansride/types` (no deps), `@kansride/config` (→ types), `@kansride/db` (→ types, config), `@kansride/auth` (→ types, db), and `@kansride/ui` (→ types). The documented build order is strictly layered: types → config → db → auth → apps. Apps (NestJS backend, Next.js admin/tracking web, Expo mobile apps) depend only on these packages — no cross-app dependencies. Root-level tooling (`package.json` scripts, `.eslintrc.json`, `.prettierrc.json`, `.nvmrc`) applies uniformly across all workspaces; `type-check` runs `tsc --noEmit` at the root using the shared base tsconfig. CI (`.github/workflows/ci.yml`) enforces a staged pipeline: lint+typecheck → build each shared package → build backend (with PostGIS + Redis service containers) → build web apps.
