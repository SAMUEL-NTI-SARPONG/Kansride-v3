## 7. Detailed Findings for D1-D4

### D1 — Admin Dashboard (BROKEN)

**What exists (real wiring, not mock):**
- `apps/admin-web/src/lib/api.ts` — fetch wrapper with `admin_token` from localStorage, 401 → `/login` redirect.
- `apps/admin-web/src/lib/hooks.ts` — React Query hooks `useDashboardStats`, `useDrivers`, `useRides`, `useUsers`, `useSubscriptions` hitting `/admin/*` endpoints.
- `apps/admin-web/src/lib/providers.tsx` — QueryClientProvider.
- Dashboard pages call the hooks and render real data with loading/error states, pagination, status badges.
- Backend `AdminModule`/`AdminController`/`AdminService` implements `GET /admin/dashboard|drivers|rides|users|subscriptions` with real DB queries, joins, pagination.

**Why it's broken:**
1. **Build failure** — `drivers/page.tsx`, `rides/page.tsx`, `users/page.tsx`, `subscriptions/page.tsx` import `'../../../../lib/hooks'` (4 levels). Correct is 3 levels (`'../../../lib/hooks'`) or `'@/lib/hooks'`. Build aborts.
2. **Login page is a dead form** — `apps/admin-web/src/app/login/page.tsx` has email/password inputs and a Sign In button with **no `onSubmit`/`onClick`, no state, no API call**. Users cannot authenticate. The api client reads `admin_token` from localStorage but nothing ever writes it.
3. **No route protection** — no `middleware.ts`, no auth check in `dashboard/layout.tsx`. `/dashboard/*` is reachable without a token. The api client redirects on 401, but the page renders first.
4. **Backend admin endpoints are unauthenticated** — `AdminController` (`apps/backend/src/modules/admin/admin.controller.ts`) has **no `@UseGuards(AuthGuard)`** and no `@RequirePermissions`. Anyone can call `/api/v1/admin/*`.
5. **No admin login endpoint** — backend `auth.controller.ts` only has OTP flow (`request-otp`, `verify-otp`, `refresh-token`). There is no email/password admin login. The admin-web login form (even if wired) has no backend to call.

### D2 — Mobile Passenger App (PARTIAL / CONTRACT MISMATCHES)

**What exists (real wiring):**
- `src/api/client.ts` — fetch wrapper with AsyncStorage token storage, auto-refresh on 401, `get`/`post`/`put`/`postPublic`.
- `src/api/socket.ts` — Socket.IO client to `/rides` namespace with auth token, `subscribeToRide`, `onRideUpdate`, `onDriverAssigned`, `onDriverLocation`.
- `src/stores/auth-store.ts`, `src/stores/ride-store.ts` — Zustand stores.
- Screens call real endpoints: login→`/auth/request-otp`, verify-otp→`/auth/verify-otp`, home→`POST /rides`, activity→`GET /rides/my-rides`, profile→`GET /users/me`, ride→`POST /rides/:id/cancel`, `POST /rides/:id/rate`.

**Contract mismatches (runtime-broken):**
1. **Login payload** — passenger `login.tsx:31` sends `{ phone: fullPhone }`; backend `auth.controller.ts:10` expects `{ phoneNumber }`. **OTP request will be ignored** (phone undefined → normalizeGhanaPhone on undefined).
2. **Verify-otp response field** — `verify-otp.tsx:67` reads `response.user.phone`; backend `auth.service.ts:150` returns `user.phoneNumber`. The passenger `User` interface also declares `phone`. **User object will have `phone: undefined`.**
3. **rideType enum** — `home.tsx:84` sends `rideType: 'standard'|'comfort'`; backend `rideTypeEnum` is `'standard_tricycle'|'priority_tricycle'|'shared'|'parcel_delivery'`. **`POST /rides` will 500** (Postgres enum violation).
4. **Fare field** — `home.tsx:96` reads `response.estimatedFare`; backend `rides.service.ts:83` returns `estimatedFarePesewas` + `fareBreakdown`. **`estimatedFare` is undefined**; UI shows fallback local estimate.
5. **`/rides/my-rides` does not exist** — `activity.tsx:33` calls `GET /rides/my-rides`. `RidesController` has no such route. `RidesService.getPassengerRides` exists but is unreachable. **Activity screen always shows empty/error.**
6. **`/users/me` returns hardcoded data** — `users.service.ts:6` `// TODO: Fetch from DB` returns `{ id, phoneNumber: '+233240000000', role: 'passenger', isVerified: true }`. **Profile screen shows fake data.**
7. **No passenger record created** — backend `auth.service.ts` creates a `users` row on first login but never a `passengers` row. `rides.passengerId` FK → `passengers.id`. **`POST /rides` will fail with FK violation** even after fixing #3.
8. **No navigation auth guard** — `app/_layout.tsx` renders `(auth)` and `(main)` unconditionally; `hydrate()` is never called. A logged-out user may land on `(main)/home`.

### D3 — Mobile Driver App (PARTIAL / CONTRACT MISMATCHES)

**What exists (real wiring):**
- `src/api/client.ts` — fetch wrapper with token storage + auto-refresh.
- `src/api/socket.ts` — Socket.IO client with `connect`, `sendLocation`, `startLocationEmission` (10s interval), `acceptRide`, `declineRide`, `subscribeToRide`, `onRideOffered`, `onRideUpdate`, `onRideCancelled`, `onError`.
- `src/stores/auth-store.ts`, `driver-store.ts`, `location-store.ts`.
- Screens: login→`/auth/request-otp` (correctly sends `{ phoneNumber }`), verify-otp→`/auth/verify-otp` (correctly reads `phoneNumber`/`role`), home→`/drivers/me`, `/drivers/go-online`, `/drivers/go-offline`, socket ride offers; subscription→`/drivers/subscribe`; earnings→`/drivers/earnings`; register→`/drivers/register`; profile→`/users/me` + `/drivers/me`.

**Contract mismatches (runtime-broken):**
1. **Driver controller reads wrong JWT fields** — `drivers.controller.ts` reads `req.user.sub` (register) and `req.user.driverId` (go-online, go-offline, location, subscribe, earnings). `auth.guard.ts:36` sets `request.user = payload` where payload = `{ userId, phoneNumber, role, iat, exp }`. **`sub` and `driverId` are always undefined → every driver endpoint throws.** The `GET /drivers/me` endpoint uses `req.user.sub` too, so even profile lookup fails. (Note: `getMe` reads `sub` but `register` also reads `sub` — inconsistent with `userId`.)
2. **`ride:offered` never emitted** — `home.tsx:80` listens for `ride:offered`; backend `dispatch.service.ts` `offerToDrivers` only logs and writes to Redis, never emits. **Driver never receives ride offers** → the core driver flow is dead.

## 11. Security Concerns

1. **Admin endpoints unauthenticated** — `AdminController` has no `AuthGuard`/`RolesGuard`/`@RequirePermissions`. `GET /api/v1/admin/dashboard|drivers|rides|users|subscriptions` are publicly readable. Anyone on the network can enumerate all users, drivers, rides, revenue. **HIGH.**
2. **Admin web has no route protection** — no `middleware.ts`, no auth check in `dashboard/layout.tsx`. `/dashboard/*` renders for everyone (data only loads if API call succeeds, but with #1 the API is also open). **HIGH.**
3. **Admin login is non-functional** — even if it were protected, there's no way to obtain an `admin_token` (dead form + no admin login endpoint). The api client's `admin_token` is never set by any code. **HIGH (blocks legitimate admin access; security through obscurity).**
4. **JWT secret env name mismatch** — backend reads `JWT_ACCESS_SECRET`/`JWT_REFRESH_SECRET` (auth.service.ts:20-21, auth.guard.ts:12-13, events.gateway.ts:51-52). `.env.example` and `shared-config/env.ts` define `JWT_SECRET`/`JWT_REFRESH_SECRET`. **In dev the backend falls back to hardcoded `'dev-access-secret'`/`'dev-refresh-secret'`** — tokens are signed with publicly known secrets. Anyone can forge a JWT. **HIGH in any non-isolated environment.**
5. **CORS wide open** — `main.ts:12` `app.enableCors({ origin: '*', credentials: true })`. `origin: '*'` with `credentials: true` is invalid per spec (browsers reject), but signals intent to allow any origin. **MEDIUM.**
6. **WebSocket CORS wide open** — `events.gateway.ts:31` `cors: { origin: '*' }`. **MEDIUM.**
7. **Throttler global only** — `ThrottlerModule` 60 req/60s global. OTP endpoint has its own 3/15min DB rate-limit (good), but no per-IP throttling on auth. **LOW.**
8. **Tracking endpoint leaks data** — `GET /rides/:id/track` is `@Public()` and returns ride status, addresses, driver first name, vehicle colour, masked plate, fare, ETA. Anyone with a ride UUID can track. This is by design (public tracking link) but ride UUIDs are guessable only via UUID entropy — acceptable. **LOW (by design).**
9. **No password/secret management** — `.env.example` ships default secrets; production guard exists in `env.ts` but backend doesn't use `getEnv()` (uses `process.env` directly). **MEDIUM.**
10. **`auth.guard.ts` instantiates `JWTService` with hardcoded fallback secrets** — if env vars missing, silently uses `'dev-access-secret'`. No fail-fast. **MEDIUM.**
